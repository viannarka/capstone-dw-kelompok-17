## 2. Keputusan wrangling

Keputusan utama dalam perancangan sistem validasi adalah **pemisahan aturan validasi menjadi aturan keras (*hard checks*) dan aturan peringatan (*soft warnings*)**:
- **Aturan Keras (Umum dan Khas Kasus):** Dirancang untuk menghentikan pipeline (`SystemExit`) jika ditemukan anomali struktural atau ketidaksesuaian data fatal, seperti kolom hilang/salah tipe, kunci duplikat (`KUNCI = [sumber, seri_kode, wilayah_kode, periode, rincian, _berkas_raw]`), nilai di luar batas satuan (mis. nilai persentase di luar rentang $0 \le x \le 100$), batas bawah melebihi batas atas, ketidaksesuaian tujuan SDG dengan nama berkas mentah (`sdg6_...`), dan inkonsistensi nilai dua tabel sanitasi aman (`var2749` vs `var2179`).
- **Aturan Peringatan:** Digunakan untuk kasus-kasus observasi empiris yang mencurigakan namun sah secara metodologis, seperti kasus sanitasi aman perkotaan lebih rendah daripada perdesaan (`daerah=URBAN < daerah=RURAL`).
- **Alternatif yang ditolak:** Menjadikan semua aturan sebagai aturan keras sehingga membatalkan data valid yang memiliki kondisi lapangan riil, atau sebaliknya hanya mencatat log tanpa menghentikan eksekusi pipeline saat terjadi galat skema fatal.
- **Alasan:** Data riil BPS mencatat bahwa pada beberapa provinsi/tahun tertentu (mis. Kepulauan Riau 2022, Sulawesi Barat 2024, Maluku 2021, Maluku Utara 2023), persentase sanitasi aman perkotaan memang lebih rendah dari perdesaan. Memperlakukan kondisi ini sebagai galat keras akan menghambat pipeline, sementara mendiamkannya akan mengaburkan temuan analisis. Oleh karena itu, aturan peringatan dicatat pada laporan `reports/validasi.md` untuk diperiksa oleh analis.

## 3. Kegagalan dan pelajaran

Pada implementasi awal, evaluasi skema Pandera berhenti seketika saat menemukan kegagalan pertama (*eager evaluation*), sehingga jika ada beberapa kolom yang bermasalah, pengembang harus memperbaiki satu per satu secara berulang. Selain itu, dependensi lingkungan Python lokal sempat memerlukan instalasi paket `pandera`, `duckdb`, dan penyesuaian path sebelum pipeline dapat dieksekusi secara mulus.

Pelajaran yang diperoleh:
1. Menggunakan parameter `lazy=True` pada `schema.validate(silver, lazy=True)` agar seluruh kasus kegagalan dikumpulkan secara komprehensif dalam satu kali jalan melalui `e.failure_cases`.
2. Otomatisasi penulisan `docs/data-dictionary.md` dari isi dataset aktual (`src/dokumen.py`) menjamin dokumentasi selalu sinkron dengan data Silver terbaru tanpa risiko perbedaan dokumentasi manual.

## 4. Bukti

Penerapan skema validasi otomatis pada dataset Silver Kasus 17 menghasilkan laporan evaluasi 11 aturan validasi:

| Ukuran | Sebelum | Sesudah | Perintah |
|---|---:|---:|---|
| Total aturan validasi teruji | 0 | 11 aturan | `python pipeline.py` |
| Aturan umum (Pandera schema) | 0 | 7 aturan (semua LOLOS) | `src/validasi/aturan.py` |
| Aturan khas kasus (Keras) | 0 | 3 aturan (semua LOLOS) | `src/validasi/khusus.py` |
| Aturan khas kasus (Peringatan) | 0 | 1 aturan (PERINGATAN 4 baris) | `src/validasi/khusus.py` |
| Status aturan keras gagal | - | 0 (tidak ada kegagalan fatal) | `reports/validasi.md` |
| Kolom Silver terdokumentasi | 0 | 15 kolom lengkap | `docs/data-dictionary.md` |

Ringkasan hasil validasi 11 aturan:
1. `kolom dan tipe`: LOLOS (semua 15 kolom wajib/tambahan hadir dengan tipe data yang tepat).
2. `rincian_dari_kamus`: LOLOS (seluruh rincian mengikuti format `total` atau `dimensi=kode`).
3. `satu_satuan_per_seri`: LOLOS (setiap seri konsisten menggunakan tepat satu satuan baku).
4. `nilai_dalam_rentang_satuan`: LOLOS (seluruh nilai persen berada pada rentang 0–100).
5. `batas_bawah_le_nilai_le_batas_atas`: LOLOS (tidak ada inkonsistensi interval kepercayaan).
6. `kunci unik`: LOLOS (tidak ada baris duplikat pada 6 kunci komposit).
7. `wilayah dan periode`: LOLOS (wilayah valid 38 provinsi + 9999; format periode terstandarisasi).
8. `tujuan_sdg_sesuai_nama_berkas`: LOLOS (kode SDG sesuai dengan berkas mentah `sdg6_...`).
9. `dua_tabel_sanitasi_aman_sama`: LOLOS (konsistensi nilai `var2749` dan `var2179`).
10. `total_di_antara_kota_desa`: LOLOS (nilai agregat berada dalam rentang wajar perkotaan-perdesaan).
11. `kota_tidak_lebih_rendah`: PERINGATAN (4 baris terdeteksi dan dilaporkan di `reports/validasi.md`).

python pipeline.py
python -m src.common.skema data/silver/silver.parquet
